## 0. Introduction

The kWire ABI defines a stable interface to all code generated by the kWire compiler in order to allow third-party  
libraries and tools to interact with it reliably.

Things that are affected by the ABI include (but are not limited to) mangling, monomorphization and inlining.

### 0.1 Meaning of Symbols

Most symbolics used in the kWire ABI specification are taken directly  
from the Kotlin programming language and may need some clarification  
for non-Kotlin developers.

* `x..y` A range from **x** to **y**, including **y**
* `x..<y` A range from **x** to **y**, excluding **y**
* `x ?: y` If **x** is present take **x**, otherwise take **y**
* `x!!` If **x** is present take **x**, otherwise throw an exception

## 2. Name Mangling

Name mangling is required to encode fully qualified declaration names into a parseable format,
which is also compatible with the underlying compilation backends.

The FQN of any declaration must be encoded in such a way in which package segments  
may be differentiated from (nested) declaration name segments, so either package name  
or the short declaration name may be reconstructed from the resulting string.

kWire uses the `_` and `.` characters to make this differentiation;

```
com_example_Foo.Bar                                 
▲  ▲▲      ▲▲  ▲▲                                   
│  ││      ││  │└────────────── Enclosed short name 
│  ││      ││  └─────────────── Nesting delimiter   
│  ││      │└────────────────── Enclosing short name
│  ││      └─────────────────── Package delimiter   
│  │└────────────────────────── 'example' package   
│  └─────────────────────────── Package delimiter   
└────────────────────────────── 'com' package       
```

In this case, we are referring to a nested class **Bar**, enclosed by the class **Foo**,  
which is located in the **com.example** package.

**Any literal `_` which is part of the package path must be escaped as `$_` to retain its meaning.**

## 3. Type Mangling

The type mangling ABI in kWire is the base for all other mangling
implementations used to encode one or more type(s) in a sequence suitable 
for use in C-compatible synthetic member names.

### 3.1 Primitive Types

Primitive types have fixed **single-character** encodings using  
lowercase letters from the ASCII range `97..122` in kWire.

| Type                                 | Mangled Name |
| ------------------------------------ | ------------ |
| `kotlin.Unit`                        | a            |
| `kotlin.Byte`                        | b            |
| `kotlin.Short`                       | c            |
| `kotlin.Int`                         | d            |
| `kotlin.Long`                        | e            |
| `dev.karmakrafts.kwire.ctype.NInt`   | f            |
| `kotlin.UByte`                       | g            |
| `kotlin.UShort`                      | h            |
| `kotlin.UInt`                        | i            |
| `kotlin.ULong`                       | j            |
| `dev.karmakrafts.kwire.ctype.NUInt`  | k            |
| `kotlin.Float`                       | l            |
| `kotlin.Double`                      | m            |
| `dev.karmakrafts.kwire.ctype.NFloat` | n            |
| `kotlin.Boolean`                     | o            |
| `kotlin.Char`                        | p            |
| `dev.karmakrafts.kwire.ctype.Ptr`    | q            |

### 3.2 Special Types

Special types are exceptions in the type mangling ABI made to shorten  
mangled member names/signatures by applying the single-character encoding  
to some common builtin non-primitive types.

Special types share their allowed character range with the primitives  
described in [this section](#11-primitive-types) of the specification.

| Type                             | Mangled Name |
| -------------------------------- | ------------ |
| `kotlin.collections.ArrayList`   | r            |
| `kotlin.collections.HashMap`     | s            |
| `kotlin.collections.List`        | t            |
| `kotlin.collections.Map`         | u            |
| `kotlin.collections.MutableList` | v            |
| `kotlin.collections.MutableMap`  | w            |
| `kotlin.Any`                     | x            |
| `kotlin.String`                  | y            |
| `kotlin.Nothing`                 | z            |

### 3.3 Class & Struct Types

Class (and struct) types have to be encoded in a special way to allow the retention of  
compile-time only type information (for generic parameters on functions and classes).

A class is always started by the characters `C$` and terminated with a matching `$C`,  
(while a struct uses `S$` and `$S` respectively)  
with the mangled, fully qualified name of the declaration sandwiched in-between those two:

```
C$kotlin_text_StringBuilder$C                         
▲▲▲     ▲▲   ▲▲            ▲▲                         
│││     ││   ││            │└── Sequence indicator (class)
│││     ││   ││            └─── Delimiter             
│││     ││   │└──────────────── 'StringBuilder' class 
│││     ││   └───────────────── Package delimiter     
│││     │└───────────────────── 'text' package        
│││     └────────────────────── Package delimiter     
││└──────────────────────────── 'kotlin' package      
│└───────────────────────────── Delimiter             
└────────────────────────────── Sequence indicator (class)
```

Similarly, a struct would be encoded as follows:

```
S$com_example_MyStruct$S                               
▲▲▲  ▲▲      ▲▲       ▲▲                               
│││  ││      ││       │└─────── Sequence indicator (struct)
│││  ││      ││       └──────── Delimiter              
│││  ││      │└──────────────── 'MyStruct' struct      
│││  ││      └───────────────── Package delimiter      
│││  │└──────────────────────── 'example' package      
│││  └───────────────────────── Package delimiter      
││└──────────────────────────── 'com' package          
│└───────────────────────────── Delimiter              
└────────────────────────────── Sequence indicator (struct)
```

#### 3.3.1 Type Arguments

Type arguments may be appended to any class, struct or builtin type after its closing `$C`.

Similar to a class or struct type itself, a type argument list is started by a `T$` and  
terminated with a matching `$T`. Between these two delimiters, any number of  
types may appear, including other class types with type arguments.

```
C$kotlin_Pair$CT$yy$T                                         
▲▲▲     ▲▲   ▲▲▲▲▲▲▲▲                                         
│││     ││   │││││││└────────── Sequence indicator (type list)
│││     ││   ││││││└─────────── Delimiter                     
│││     ││   │││││└──────────── 'kotlin.String' type          
│││     ││   ││││└───────────── 'kotlin.String' type          
│││     ││   │││└────────────── Delimiter                     
│││     ││   ││└─────────────── Sequence indicator (type list)
│││     ││   │└──────────────── Sequence indicator (class)    
│││     ││   └───────────────── Delimiter                     
│││     │└───────────────────── 'Pair' class                  
│││     └────────────────────── Package delimiter             
││└──────────────────────────── 'kotlin' package              
│└───────────────────────────── Delimiter                     
└────────────────────────────── Sequence indicator (class)    
```

This would encode the `Pair<String, String>` type.  
As mentioned above, type argument lists may also appear recursively:

```
C$kotlin_Pair$CT$ytT$y$T$T                                    
▲▲▲     ▲▲   ▲▲▲▲▲▲▲▲▲▲▲▲▲                                    
│││     ││   ││││││││││││└───── Sequence indicator (type list)
│││     ││   │││││││││││└────── Delimiter                     
│││     ││   ││││││││││└─────── Sequence indicator (type list)
│││     ││   │││││││││└──────── Delimiter                     
│││     ││   ││││││││└───────── 'kotlin.String' type          
│││     ││   │││││││└────────── Delimiter                     
│││     ││   ││││││└─────────── Sequence indicator (type list)
│││     ││   │││││└──────────── 'kotlin.collections.List' type
│││     ││   ││││└───────────── 'kotlin.String' type          
│││     ││   │││└────────────── Delimiter                     
│││     ││   ││└─────────────── Sequence indicator (type list)
│││     ││   │└──────────────── Sequence indicator (class)    
│││     ││   └───────────────── Delimiter                     
│││     │└───────────────────── 'Pair' class                  
│││     └────────────────────── Package delimiter             
││└──────────────────────────── 'kotlin' package              
│└───────────────────────────── Delimiter                     
└────────────────────────────── Sequence indicator (class)    
```

This would encode the `Pair<String, List<String>>` type.
